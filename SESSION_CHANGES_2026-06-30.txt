Automated Phishing Analyzer - Session Changes
Date: 2026-06-30

Goal
- Fix confirmed analyzer bugs.
- Improve GUI spacing/alignment to reduce overlap.
- Add a way to show a screenshot preview of the analyzed website in the tool.

What I changed

1. Backend fixes in url_scraper.py
- Fixed the local reputation DB read bug.
  - Changed PRAGMA parsing from column index values to actual column names.
  - Result: reputation data like avg_risk and scan_count can now be read correctly.

- Fixed double-counting in scan history and domain aggregates.
  - The analyzer previously recorded one heuristic scan and then another AI scan for the same run.
  - It now records one final scan per analysis run using the final chosen result.

- Refreshed saved reputation data after recording the final scan.
  - Result: extracted_data.json now reflects the latest reputation snapshot.

- Fixed binary image asset saving.
  - Image assets are now written using binary mode instead of text mode.
  - Result: downloaded image files are no longer corrupted by text encoding.

- Added optional screenshot capture metadata.
  - The analyzer now attempts a best-effort page preview capture and stores the result in _page_preview.
  - If screenshot capture is unavailable, the saved output contains an error/hint instead of silently doing nothing.

2. GUI fixes in phishing_analyzer_gui.py
- Increased the minimum window size.
- Reworked result rendering to use wrapped text blocks instead of fixed single-line assumptions.
- Made the verdict card more responsive by stacking content on narrower widths.
- Improved spacing in long sections such as:
  - Threat Intelligence
  - Downloaded Assets
  - AI Analysis Result
  - JavaScript Analysis
  - CSS Analysis
  - Findings Summary
- Added a new Website Preview section to show a captured screenshot when available.

3. Screenshot support
- Added capture_page.js.
  - This uses Node.js + puppeteer-core + a local Chrome/Chromium executable.
  - The Python analyzer calls it only when Node.js and BROWSER_PATH are available.

- Added a package.json script:
  - npm run capture:screenshot

4. Dependency and documentation updates
- Updated requirements.txt and pyproject.toml to include:
  - python-whois
  - Pillow
- Updated README.md to mention:
  - improved responsive GUI spacing
  - Website Preview support
  - screenshot setup requirements

How screenshot preview works
- The GUI can display a screenshot of the analyzed site if the environment has:
  - Node.js installed
  - npm install run in the repo
  - BROWSER_PATH set to a local Chrome/Chromium executable

Recommended setup example
- npm install
- export BROWSER_PATH=/usr/bin/google-chrome

Expected output
- A file named page_preview.png will be saved under:
  - scraped_sites/<domain>/page_preview.png
- The GUI will show that image inside the Website Preview section.

If screenshot capture is not available
- The analyzer will still run.
- The GUI will show a setup hint in the Website Preview section instead of an image.
